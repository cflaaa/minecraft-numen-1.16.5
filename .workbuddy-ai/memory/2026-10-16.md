## 背景
上一轮把运行环境从 Windows 换到 Debian 12：装了 Linux JDK（Temurin 17.0.20.1+1，
与 Windows 同版本），并用它把工程"在临时副本里"构建通了（`:core:build` 绿、62 单测 0 失败、
jar 968 类无缺无多）。但测试工具链全是 Windows 口径（`C:\...`、PCL 客户端、`taskkill`、`;` classpath）。

## 本轮完成：Linux 版测试环境（新增 `tools/linux/`）

- **`tools/linux/build.sh`** —— Linux 构建包装：Linux JDK + 仓库根 `.toolchain/gradle-7.6.4`
  （缺执行位 → `sh` 调）+ `bmclapi-fix.init.gradle`（BMCLAPI 把未缓存的 `com.mojang` 302 到失效主机，
  init 脚本排除它 → 落到 `libraries.minecraft.net`）。
- **`tools/linux/setup-testserver.sh`** —— 在 `.testserver/` 装标准 Fabric 服：
  Fabric 安装器（带重试）→ 原版 server；fabric-api **把 loom 缓存里的 45 个模块 jar 铺进 mods/**
  （maven 上的 fabric-api 是 ~2KB 聚合桩，不含模块，直接铺会导致 `NoClassDefFoundError:
  ServerPlayNetworking$PlayChannelHandler`）；打开 MCP（`mcp_server.json` enabled=true, 8766）。
- **`tools/linux/server.sh`** —— start/stop/status/console(FIFO)/tail。要点：
  `setsid` 新进程组（stop 杀整组，防孤儿占 `session.lock`）；**必须 cd 进 TS**（launcher 按 cwd 找
  `server.jar`、写 `logs/`）；启动前**旋转 `latest.log`**（否则 `Done (` 匹配旧行误报就绪）。
- **`tools/linux/owner-bot/`** —— mineflayer 假主人（`owner-bot.js` + package.json），替代 Windows 图形客户端。
- **`tools/_perm_live_common.py`** —— 改成**跨平台**：`IS_WIN` 分支；Linux 走
  `java -jar fabric-server-launch.jar` + owner-bot；`libraries()` 在 Linux 返 `(None, [])`；
  `kill_all` 用 terminate/kill。9 个 e2e 脚本因此无需改动即可在 Linux 跑。

## 环境坑（Linux 新记）
- **本机 25565–25586 被 MSLX 群占**（还发现一个旧 `keepalive.js` 假玩家、一个 MSLX 的
  `fabric-server-mc.1.16.5-loader.0.14.25` java）。Linux 测试服改用空闲口 **25987**。
- `pkill -f "<pattern>"` 会**匹配到自己那条命令行**（自毙，退出码 143）。用 `pgrep -x java` /
  `pkill -x java`（按进程名精确匹配，不会命中 bash）。
- maven.fabricmc.net 很抖：`fabric-installer` 一度 16 B/s → reset；带重试才过。
