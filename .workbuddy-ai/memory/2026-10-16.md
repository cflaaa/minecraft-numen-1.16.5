## 0003 主线程寻路「拷快照」——定位 + 廉价拷贝（2026-10-16 晚）
- **量化**（临时埋点，真机）：每段 `PalettedContainer.write` ≈ 240µs、`read` ≈ 18µs、alloc ≈ 0。
  逐字节码看：`write` 会 **把 4096 格逐格重打包**成新 `BitStorage`（`Mth.ceillog2` + new BitStorage + 循环 set）——
  这就是拷贝 99% 的开销。上游 1.20 用 `PalettedContainer.copy()`（无此问题）。
- **修**：新增 pathing 接口 `PalettedContainerAccess` + core mixin `PalettedContainerAccessor`
  （`@Accessor` 露 `palette`/`storage`/`bits`）；`WorldSnapshot.copy` 改成**拷 raw `long[]` + 共享调色板**
  （调色板只追加/整体换，不就地重排 → 共享安全；见 WorldSnapshot 注释）。`WorldSnapshot` 内部类型
  从 `PalettedContainer[][]` 换成自带的只读 `Section`（palette+storage，索引 `(y<<8)|(z<<4)|x`）。
- **真机前后**（MSLX）：拷快照 **p50 147.8ms → 1.9ms（~55×）**、p95 157.7 → 8.8、占比 99% → 16%；服务端不崩。
  残留：单刻总计 p50 ~9ms（转向/成本模型），非拷贝；冷启动首搜有 150ms 离群（JIT，非拷贝）。
- ⚠️ **换 jar 必须 stop→copy→start**：直接 copy 后 restart 会撞热替换（`ZipFile invalid LOC header`）。
