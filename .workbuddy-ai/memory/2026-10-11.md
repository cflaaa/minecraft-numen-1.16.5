**结论**：`use_block` 点她**脚下**那一格时，`Aim.use` 挑的是它的**上面**，算出来的放置点
= 她站的那一格 → **原版不许把方块放进玩家自己身体里**，`BlockItem.place` 直接 `FAIL`，
`PlayerHands.use` 于是返回 `Nothing`。真玩家此时也放不下（要跳起来才放得下）。**模组行为正确，e2e 的场景选错了。**

**怎么定案的**（前两步都排除了，第三步才抓到）：

### 部署形态评估：多人联机服务器该用哪套（2026-10-11，只查代码没改）

用户问「原项目 vs A 计划哪个适合多人联机服务器」。查证的事实（都在代码里）：

- `fabric.mod.json` 是 `environment: "*"`，但**核心全在服务端**（同伴=服务端假玩家、大脑、工具、
  征询走聊天）；客户端只有 G 面板 + 离线账号解禁。**没有 `custom` 载荷要求 → vanilla 客户端能连**。

  「那份是服务端全局配置（里面有 API key）」）。客户端那份只是 UI 偏好，另存 `config/numen_client.txt`。

  在 Minecraft 里那个线程就是**服务端主线程**」。HTTP 是 `HttpClient.sendAsync`（异步、不占主线程），
