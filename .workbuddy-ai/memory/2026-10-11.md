- 用 `so-probe.py`（本机起专用服 + 真客户端直连 + 可召唤同伴 + `/stop`）驱动真机试跑。

- ⚠️ **关服瞬间 `T lost connection: Internal Exception: java.lang.StackOverflowError`**：**定型为原版 1.16.5 行为**（PORTING.md §15.3、skill 坑 16）。链路全在 vanilla：netty 线程 → `handleMovePlayer:806` → `PacketUtils.ensureRunningOnSameThread:18/19` → `BlockableEventLoop.execute:94` 走**内联**分支（因 `MinecraftServer:1287` 覆写 `super.scheduleExecutables() && !isStopped()`，`stopped` 后恒 false）→ λ 里 `p.handle(l)` 又回去 → 无限递归。`stopped=true` 在 `runServer()` 里早于 `stopServer()`（`Saving players` 在里面）→ 原版自带 ~1s 窗口。

### ✅ 放置账本那条已定案（2026-10-11 下午）：**不是 bug，是原版规矩**

**结论**：`use_block` 点她**脚下**那一格时，`Aim.use` 挑的是它的**上面**，算出来的放置点
= 她站的那一格 → **原版不许把方块放进玩家自己身体里**，`BlockItem.place` 直接 `FAIL`，
`PlayerHands.use` 于是返回 `Nothing`。真玩家此时也放不下（要跳起来才放得下）。**模组行为正确，e2e 的场景选错了。**

**怎么定案的**（前两步都排除了，第三步才抓到）：
1. **不是手里没拿方块**：`/data get entity Alice SelectedItem` → `{id:"minecraft:gold_block",Count:43b}`，选中槽 0 就是金块。
2. **不是方块种类 / 放置机制**：`perm-place-probe2/3.py` 在受控场地搭墙，点 stone/grass_block/dirt/自然草
   四种**全部放置成功**（⚠️ 但那批目标其实都偏了一格 —— 我的 `pos_of` 用了 `int()` 截断，
   -160.5 → -160，正确是 -161，所以「点脚下」根本没被真正测到）。
3. **加调试日志**（`Acts.useBlock` 临时打 `hitPos/face/loc/placeAt/placeState/sneak/main` + `use` 类型），
   在失败的 e2e 上抓到：`face=up placeAt=(209,4,-155) placeState=air main=43 gold_block` 而 `use=Nothing`；
   成功那轮 `placeAt` 与她站的那一格**不是同一格**。五个数据点完美吻合「placeAt == 她自己那一格 → 拒绝」。

**vanilla 证据**（loom 缓存 merged-named jar，`javap -c`）：
`CollisionGetter.isUnobstructed(BlockState,BlockPos,CollisionContext)` 的默认实现
**把 `null` 当「谁放的」传下去**，于是不排除放置者自己：
```java
default boolean isUnobstructed(BlockState state, BlockPos pos, CollisionContext ctx) {
   VoxelShape shape = state.getCollisionShape(this, pos, ctx);
   return shape.isEmpty() || this.isUnobstructed((Entity) null, shape.move(x, y, z));  // ← null！
}
```
`BlockItem.canPlace(ctx, state)` 用它 → `getPlacementState` 返回 null → `place` 返回 `FAIL`。
（顺手核过：`ServerPlayerGameMode.useItemOn` 本身**没有** `mayInteract` 检查，走的是
`stack.useOn(new UseOnContext(...))`；`spawn-protection=0`，不是出生点保护。）

**改了两处**：
- `Acts.useBlock`：`use == Nothing` 且「放置点 == 她站的格子」且主手是 `BlockItem` 时，
  回一句如实的说明（「换一面，或者先把这一格空出来再放」），别让模型以为「点了没反应」是方块的问题。
- `perm-e2e.py` 第 5 步：改成在她旁边 `/setblock` 搭一格 stone，点它的**上面**（放置点落在它头顶、不压她）。
  顺带把 `_perm_live_common.pos_of` 的坐标取整从 `int()` 截断改成 `math.floor`。
